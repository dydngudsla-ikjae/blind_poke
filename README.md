# BlindPoke

정체를 숨긴 포켓몬을 단서로 식별하고, 동료로 포획해 본거지를 건설·운영하는 브라우저 게임입니다.

## 현재 게임 흐름

현재 플레이 루프는 다음 순서로 연결됩니다.

1. 스타팅 드래프트에서 실루엣 후보를 골라 서로 다른 포켓몬 3마리를 영입한다.
2. 본거지에서 포켓몬을 관리하고, 빈 부지에 건물을 착공하거나 다음 턴을 진행한다.
3. 탐험에서 미확인 개체를 선택하고 단서를 사용해 정체를 추리한다.
4. 이름을 정확히 맞히면 남은 우호도를 확률로 사용해 포획을 시도한다.
5. 포획한 포켓몬을 성장시키고 전투 엔트리에 등록한다.
6. 지도에서 인접 지역에 도전해 포켓몬 배틀로 영토를 확보한다.
7. 확보 지역의 수입과 건설 진행을 바탕으로 본거지를 확장한다.

게임 상태는 주요 행동 직후 브라우저 `localStorage`에 자동 저장됩니다. 저장된 게임이 있으면 드래프트를
건너뛰고 본거지에서 이어서 시작하며, 이전 저장 형식은 현재 건물 상태 구조로 마이그레이션합니다.

## 현재 적용된 게임 정책

### 턴과 행동 에너지

- 한 턴의 최대 행동 에너지는 5입니다.
- `다음 턴`을 누르면 에너지가 5로 회복됩니다.
- 탐험은 에너지 2, 건물 착공은 에너지 1을 소비합니다.
- 공사 중인 건물에 인력을 추가하는 행동은 인원수와 관계없이 에너지 1을 소비합니다.
- 지도에서 지역 공격을 시작하면 에너지 2를 소비합니다.
- PC에서 먹이, 경험치 사탕, 기술 지도를 사용할 때 각각 에너지 1을 소비합니다.

### 건설

- 본거지에는 부지가 10개 있으며, 현재 개방된 부지만 사용할 수 있습니다.
- 건물 한 채가 부지 한 칸을 차지하고 같은 종류의 건물을 여러 채 지을 수 있습니다.
- 건물은 밭, 레스토랑, 훈련소, 제작소, 치료소의 5종입니다.
- 기본 건설 기간은 3턴입니다.

| 건설 인력 | 완공 기간 |
|---:|---:|
| 1마리 | 3턴 |
| 2마리 | 2턴 |
| 3마리 이상 | 1턴 |

- 착공 직후에는 시간이 흐르지 않고, 다음 턴부터 남은 기간이 감소합니다.
- 인력이 한 마리도 없으면 공사가 일시정지됩니다.
- 인력을 추가해도 이미 단축된 남은 시간이 다시 늘어나지 않습니다.
- 인력 회수와 공사 취소가 가능하며, 소비한 에너지는 환불되지 않습니다.
- 완공된 건설 인력은 해당 건물의 대기 인력으로 남습니다.

### 타입별 전용 직무

내정 직무는 타입 적성 보너스 방식이 아니라 **해당 타입만 수행할 수 있는 전용 행동**으로 운영합니다.
타입이 맞지 않는 포켓몬은 그 직무에 배치할 수 없습니다. 복합 타입 포켓몬은 자신이 가진 두 타입에
해당하는 직무를 모두 수행할 수 있습니다.

| 타입 | 주 역할 | 세부 특성 |
|---|---|---|
| 풀 | 씨앗 생성 | 열매·규토리·허브 씨앗 획득 |
| 땅 | 땅 평탄화 | 시설·밭 슬롯 확장 |
| 벌레 | 밭 일구기 | 씨앗을 사용할 경작지 준비 |
| 물 | 열매 생산 | 경작지에서 작물 재배·수확 |
| 불꽃 | 요리 | 열매와 재료를 음식으로 가공 |
| 얼음 | 냉장 | 자원 부패 방지·보관량 증가 |
| 격투 | 훈련 | 기술머신 획득 |
| 에스퍼 | 육성 연구 | 경험치 사탕 생산 |
| 바위 | 재료 채취 | 석재·광석·제작 재료 획득 |
| 강철 | 재화 주조 | 광석을 화폐·판매품으로 가공 |
| 전기 | 도구 제작 | 재료와 돈으로 내정 도구 제작 |
| 비행 | 치안 | 상대 첩보 탐지 |
| 드래곤 | 치안 | 상대 시설 방해 탐지·격퇴 |
| 악 | 침투 | 상대 시설 생산량 저하 |
| 고스트 | 침투 | 상대 포켓몬·시설 정보 획득 |
| 페어리 | 치료 | 체력·기력 회복 아이템 생산 |
| 독 | 치료 | 독·마비·화상 등 상태이상 치료 |
| 노말 | 범용 보조 | 모든 시설의 작업 보조 |

농업 생산 체인은 다음 세 갈래의 씨앗으로 시작합니다.

| 씨앗 계열 | 최종 용도 |
|---|---|
| 규토리 | 몬스터볼 계열 포획 도구 제작 |
| 열매 | 포켓몬이 지니는 아이템 또는 요리 재료 |
| 허브 | 포켓몬 성격 변경 |

농업과 확장 직무의 역할은 다음과 같이 구분합니다.

- 풀 타입의 `씨앗 생성`은 규토리·열매·허브 계열의 씨앗을 확보합니다.
- 벌레 타입의 `밭 일구기`는 씨앗을 심어 재배를 시작하는 역할을 담당합니다.
- 물 타입의 `열매 생산`은 심은 씨앗의 재배 작업력을 채우고 결과물을 수확합니다.
- 얼음 타입의 `냉장`이 없으면 수확한 규토리·열매·허브는 일정 턴이 지난 뒤 부패해 사라집니다.
- 땅 타입의 `땅 평탄화`는 누적 작업력을 채워 새로운 건설 부지를 영구 해금합니다.
- 노말 타입은 전용 타입 작업자가 한 마리 이상 배치된 직무만 보조할 수 있습니다. 노말 타입만으로는 직무를 가동하거나 막힌 생산 체인을 대신할 수 없습니다.

현재 확정된 배치 원칙은 다음과 같습니다.

- 전용 직무의 주 작업자는 반드시 표에 지정된 타입이어야 합니다.
- 복합 타입은 두 타입 중 어느 쪽의 전용 직무에도 배치할 수 있습니다.
- 노말 타입은 독립 생산 직무 대신 모든 시설의 보조 인력으로 사용합니다.
- 필요한 타입의 포켓몬이 없으면 해당 직무와 연결된 생산 체인은 중단됩니다. 노말을 포함한 대체 타입이나 기본 생산은 제공하지 않습니다.
- 생산 체인의 중단은 의도된 제약이며, 필요한 타입을 탐험과 포획으로 확보하는 것이 핵심 진행 방식입니다.
- 전용 직무 하나에는 해당 타입의 포켓몬을 최대 3마리까지 배치할 수 있습니다.
- 작업 성능은 포켓몬 수나 레벨이 아니라 배치된 포켓몬들의 특수능력 합계로만 계산합니다.
- 포켓몬 한 마리의 특수능력 최대치는 100이므로 직무 하나의 기본 작업력 최대치는 300입니다.
- 매 턴 발생한 작업력은 직무별 진행도에 누적되며, 생산에 사용하고 남은 작업력은 다음 턴으로 이월합니다.
- 초기 밸런스에서는 반복 생산 직무의 결과물 1개당 필요한 작업력을 모두 100으로 통일합니다.
- 실제 플레이에서 특정 생산 체인의 병목이나 과잉 생산이 확인되면 직무별 필요 작업력을 조정합니다.
- 땅 평탄화와 밭 일구기처럼 슬롯을 늘리는 영구 작업은 반복 생산과 분리하며, 완료에 필요한 작업력은 별도로 결정합니다.
- 노말 보조가 작업력에 미치는 효과와 보조 인원 제한은 구현 전에 별도로 결정합니다.
- 비행·드래곤의 치안과 악·고스트의 침투는 지도 및 상대 세력 시스템과 함께 구현합니다.
- 직무별 입력·출력 자원의 정확한 수량은 아직 확정하지 않았습니다.

### 탐험, 식별, 포획

- 탐험 한 번에 미확인 포켓몬 후보 3마리가 나타납니다.
- 박사 상담은 능력치, 기술, 특성, 타입 단서를 제공합니다.
- 직접 관찰은 키와 몸무게를, 본인확인서 대조는 외곽 실루엣을 보여줍니다.
- 단서를 한 번 사용할 때마다 우호도가 8 감소합니다.
- 이름을 틀릴 때마다 우호도가 20 감소합니다.
- 우호도는 개체별 최저치 아래로 내려가지 않습니다.
- 이름을 정확히 맞힌 시점의 우호도가 최종 포획 성공 확률이 됩니다.
- 포획에 실패하면 개체는 도주합니다. 식별을 포기하면 정답을 공개하지 않고 정체를 모르는 상태로 탐험을 종료합니다.
- 정체를 모르는 상태에서 포획을 시도할 수는 없습니다. 이름을 정확히 맞힌 경우에만 포획 판정을 진행합니다.
- 포획에 성공한 개체는 즉시 로스터와 저장 데이터에 추가됩니다.

### 포켓몬 관리

- PC에서 우호도, 레벨, 경험치, 특수능력, 건물 배치 상태를 확인합니다.
- 먹이는 우호도를 15 회복하고, 사탕은 기본 경험치 20을 지급합니다.
- 기술머신은 특수능력을 5 올리며 최대치는 100입니다.
- 전투 엔트리는 최대 6마리이며 확장할 수 없습니다. 6마리가 등록된 상태에서는 다른 포켓몬을 등록하려면 기존 엔트리를 먼저 해제해야 합니다.
- 엔트리 편성 화면에서 PC 포켓몬을 6개 슬롯으로 드래그해 등록하고, 슬롯 사이에서 출전 순서를 바꾸거나 PC로 되돌려 해제할 수 있습니다. 더블클릭도 보조 조작으로 지원합니다.
- 엔트리 1번 슬롯이 선봉이며 포켓몬이 쓰러지면 저장된 슬롯 순서대로 다음 포켓몬이 출전합니다.
- 부품 3개로 지닌도구를 제작하고 포켓몬에게 장착할 수 있습니다.
- 다음 턴마다 기본 우호도가 2 감소합니다. `먹다남은음식`과 `평온의방울`은 이 감소에 영향을 줍니다.
- 우호도 감소만 현재 적용되어 있으며, 낮은 우호도에 따른 이탈은 아직 구현하지 않았습니다.

### 트레이너와 우호도 성향

- 새 게임을 시작하면 주요 트레이너 목록에서 플레이어의 트레이너를 무작위로 결정합니다.
- 스타팅 3마리를 모두 선택하기 전까지 트레이너의 이름과 정체를 공개하지 않습니다.
- 트레이너의 `pokemon`에 포함된 진화 계열은 인연 포켓몬으로 판정하고 초기 우호도에 10을 더합니다.
- 인연 포켓몬이 아니면서 `specialtyTypes`와 타입이 일치하면 초기 우호도에 5를 더합니다.
- 인연 포켓몬 보너스와 선호 타입 보너스는 중첩하지 않으며, 둘 다 해당하면 인연 포켓몬의 +10만 적용합니다.
- 트레이너의 포켓몬 목록은 우호도 판정용이며, 해당 포켓몬을 처음부터 소유하거나 엔트리에 지급하지 않습니다.
- 전설·환상 포켓몬도 동일하게 우호도 인연만 나타내며 자동으로 지급되지 않습니다.

스타팅 포켓몬을 고를 때는 트레이너 정체와 우호도 숫자 대신 관계 신호만 표시합니다.

| 신호 | 의미 |
|---|---|
| 초록불 | 인연 포켓몬 또는 선호 타입이라 우호도 보너스가 있음 |
| 흰색불 | 특별한 우호도 보정이 없음 |
| 빨간불 | 비선호 관계로 초기 우호도가 5 감소함 |

초록불은 인연 `+10`과 선호 타입 `+5`를 구분해서 알려주지 않습니다. 스타팅 3마리를 모두 선택하면
트레이너의 이름과 선호 타입을 공개합니다.

- 선호 타입은 `{ id, nameKr }` 형태로 저장합니다. 판정에는 `type.json`과 포켓몬 데이터가 공통으로 사용하는 타입 ID를 사용하고, 이름은 JSON 가독성을 위해 함께 둡니다.
- 비선호 타입은 별도 저장하지 않고, 선호 타입의 `relationMap.damageFrom`이 1보다 큰 타입으로 계산합니다.
- 여러 선호 타입을 가진 트레이너는 각 선호 타입의 약점을 합쳐 비선호 타입으로 사용하며, 선호 타입과 겹치면 선호 판정을 우선합니다.
- 관계 판정 우선순위는 `인연 포켓몬 → 선호 타입 → 비선호 타입 → 중립`입니다.

### 타운맵과 정찰

- 월드맵 배경에는 향후 확장을 위한 40개 거점 공터가 있으며, 현재는 그중 시작 영역 10개와 연결 관계만 활성화합니다. 배경의 섬과 숲은 시각적 표현이며 별도 지형 효과를 갖지 않습니다.
- 40개 거점은 각각 고정 ID, 월드 좌표, 소속 구역과 인접 거점 목록을 가집니다. 빠른 개발을 위해 현재 10곳만 활성화하며 나머지 30곳은 `준비 중` 상태로 저장합니다.
- `준비 중`인 30곳에는 게임 내 해제 조건이 없습니다. 기능 개발이 완료되는 대로 별도 플레이 조건 없이 활성 범위를 늘립니다.
- 월드맵은 버튼 또는 마우스 휠로 확대·축소할 수 있고, 확대 상태에서 드래그해 이동할 수 있습니다.
- 새 게임마다 플레이어 본거지 1곳, 서로 다른 상대 트레이너 6명의 점유지, 미점령지 3곳을 무작위로 배치합니다.
- 상대 트레이너는 플레이어에게 배정된 트레이너와 중복되지 않습니다.
- 본거지 이외의 거점은 처음에 이름, 점유 여부와 트레이너 정체를 공개하지 않습니다.
- 플레이어가 확보한 거점과 연결된 미확인 거점만 정찰할 수 있습니다.
- 정찰이 끝나면 거점 이름과 미점령 여부 또는 점유 트레이너의 이름·선호 타입을 공개합니다.
- 거점 배치와 정찰 결과는 저장하고 다시 불러올 수 있습니다.

### 점령과 배틀 예정 정책

- 정찰한 인접 지역만 공격할 수 있도록 확장할 예정입니다.
- 본거지와 모든 점령 지역은 동일하게 최대 10개의 건설 부지를 가집니다.
- 신규 점령 지역은 부지 2칸이 개방되며, 나머지는 땅 타입의 땅 평탄화로 해금합니다.
- AI 지역에는 기존 5종 건물 중 일부가 건설되어 있고, 점령 후 그중 하나를 선택해 승계할 수 있습니다.
- 미정찰 지역은 전장의 안개 상태이며 AI 건물, 배치 포켓몬과 적 전투 엔트리를 모두 공개하지 않습니다.
- 지역 공격에 승리한 뒤에만 승계할 수 있는 AI 건물 목록을 공개합니다.
- 고스트 타입의 침투는 미점령 지역의 숨겨진 포켓몬·시설 정보를 공격 전에 획득하는 수단으로 구현합니다.
- 승계한 건물은 완공 상태로 첫 번째 부지를 차지하지만 작업자는 없으므로, 필요한 타입 포켓몬을 새로 배치해야 가동됩니다.
- 원하는 건물이 없으면 승계를 포기하고 개방된 부지를 비운 상태로 사용할 수 있습니다.
- 선택하지 않은 AI 건물은 점령 과정에서 소실되며 플레이어가 사용할 수 없습니다.
- 지역별 전용 특성, 전용 건물과 별도 건물 이미지는 두지 않습니다. 모든 지역이 같은 건물·직무 규칙을 사용합니다.
- 초반 지역은 적 1마리, 후반 지역은 적 2마리로 구성됩니다.
- 전투 엔트리가 있으면 해당 포켓몬들이 출전하고, 비어 있으면 전체 로스터가 임시 출전합니다.
- 실제 포켓몬 기술 데이터의 위력, 명중률, 물리·특수 분류와 타입 상성을 사용합니다.
- 속도가 높은 포켓몬이 먼저 행동하며, 쓰러지면 남은 팀원으로 자동 교체합니다.
- 승리하면 지역을 확보하고, 확보한 시작 지역 외 영토 하나당 다음 턴에 자금 3을 얻습니다.
- 자금은 현재 저장 상한을 넘지 않습니다.
- 변화 기술은 현재 피해 없이 로그만 출력하며, 상태이상·PP·특성·배틀 도구 효과는 아직 적용하지 않습니다.

### 현재 개발 경계

건물 건설까지의 상태·규칙·저장 흐름은 현재 완성 기준선입니다. 건물 내부 직무 배치와 직무별 자원 생산은
새 `buildingId` 상태 모델로 다시 구현할 예정이므로, 현재 자원·상점 UI가 존재하더라도 완성된 경제 루프로
간주하지 않습니다. 상세 개발 순서와 미확정 정책은 [PLAN.md](./PLAN.md)를 기준으로 합니다.

## 실행

```bash
npm install
npm run dev
```

개발 서버는 기본적으로 `http://127.0.0.1:5175`에서 실행됩니다.

## 검증

```bash
npm run build
npm run test:unit
npm run test:smoke
```

- `build`: TypeScript 검사와 Vite 프로덕션 번들 생성
- `test:unit`: Vitest로 게임 규칙·reducer·저장 스키마·React 컴포넌트 검증
- `test:smoke`: 실제 Chrome에서 드래프트 → 본거지 → 건설 → 저장 복원 → 사냥·식별 → 지도·배틀 흐름 검증

## 기술 구성

- React
- TypeScript
- Vite
- Zod 저장 데이터 검증
- Vitest + React Testing Library
- Playwright 스모크 테스트
- 브라우저 `localStorage` 저장

## 주요 구조

```text
src/
  App.tsx                 # 데이터 로드와 화면 라우팅
  domain/                 # 공용 타입과 순수 게임 규칙
  game/                   # GameProvider, reducer, 상태 마이그레이션
  screens/                # 드래프트·본거지·사냥·지도·배틀 React 화면
  services/               # 데이터와 저장소 접근
tests/
  smoke.mjs               # 전체 핵심 흐름 브라우저 테스트
assets/                   # 배경과 건물 이미지
data/                     # 포켓몬·타입·기술·특성 데이터
```

현재 개발 순서와 확정된 게임 규칙은 `PLAN.md`를 기준으로 합니다.
